# Qnector v0.4.55 — Windows Terminal reliability

## Fixed

- Fixes [#1](https://github.com/queenleonidasth/Qnector/issues/1): clicking the Workspace **Terminal** button could show a Windows "cannot find" dialog or leave no interactive shell open, particularly for workspace paths containing spaces.
- Removes fragile `cmd.exe /c start` quoting and app-execution-alias fallbacks. Uses an encoded PowerShell helper that launches an interactive shell in the selected workspace, then checks whether it exits immediately.
- Uses appropriate startup arguments for Windows PowerShell, PowerShell 7 and Command Prompt; supports other configured shells without adding PowerShell-specific arguments. Falls back to built-in PowerShell when a custom shell fails.
- Adds regression coverage for paths containing spaces, apostrophes and shell metacharacters, and updates the desktop UI contract test.

## Updating

Open Qnector's **Updates** panel, check for updates, download **v0.4.55**, and install. Both Windows Setup and Portable editions use the official GitHub Release assets. The update includes the existing v0.4.54 Plan Mode 2.0 functionality.

## Notes

The Windows executables are intentionally unsigned (`Authenticode: NotSigned`), consistent with the prior release. Obtain them from this repository's GitHub Release; Windows SmartScreen may display a warning. The update flow validates GitHub asset digests when provided.

Automated tests and packaged smoke checks are run as part of the release gates. Final interactive verification of the Workspace Terminal button should be performed on the installed app before closing issue #1.
