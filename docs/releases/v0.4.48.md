# Qnector v0.4.48 — Skills discovery keyboard focus fix

## Changes

- Fixed the **Discover skills.sh** dialog so its search field receives keyboard focus immediately when the dialog opens.
- Removed the competing browser `autoFocus` path and extended the shared modal focus trap with an explicit initial-focus target.
- Explicit initial focus is applied synchronously after the React commit, while dialogs without a preferred target retain the existing requestAnimationFrame fallback.
- Added regression coverage to prevent the close button or parent drawer from stealing initial focus from the skills.sh search field.

## Verification

- Reproduced the v0.4.47 bug on the installed desktop app: Windows UI Automation reported keyboard focus on **Close skills.sh discovery** instead of the search edit control.
- Verified the search/backend path independently on the installed app: entering a query enabled Search, skills.sh returned results, and install controls rendered normally.
- Electron/CDP verification after the fix showed `document.activeElement` is the Discover search `INPUT` immediately after opening the dialog, before any click, and typing updates the controlled value and enables Search.
- Skill Manager focused regression tests: 8/8 passed.
- Full Windows test suite: 342/342 passed.
- TypeScript typecheck, ESLint with zero warnings, production build, Prettier, and `git diff --check` passed before release versioning.
- Final Windows packaging/release gates and packaged executable smoke tests must pass for the v0.4.48 candidate before publication.
