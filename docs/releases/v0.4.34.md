# Qnector v0.4.34

Qnector can now invoke configured local stdio MCP servers through its existing
`system` tool, without adding another top-level ChatGPT tool.

- `system.mcp_servers` lists upstream servers and environment variable names.
- `system.mcp_tools` discovers tool schemas with query filtering and result limits.
- `system.mcp_call` forwards arguments and preserves upstream error and truncation
  information. Activity records argument keys rather than argument values.
- Configure upstreams in `%APPDATA%\Qnector\external-mcp.json`. Optional `dpapiEnv`
  entries load Windows DPAPI-protected environment values when spawning a server.
- Each discovery or call opens and closes its own upstream client connection.
- Windows packaging now requires the External MCP stdio integration tests.

Validation: TypeScript typecheck, ESLint and all 247 tests across 40 files passed.
The new six integration tests exercise a real local stdio peer, including
handshake, discovery, argument/environment forwarding, child cleanup and error
preservation during truncation. Changed TypeScript files and the tool reference
pass Prettier checks.

This release retains the v0.4.33 connection diagnostics. It does not claim to fix
ChatGPT's web message delivery timeouts or change the Skill routing warning policy.
