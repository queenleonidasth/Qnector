# Qnector v0.4.37 — MCP reliability and opt-in Durable Runtime

This is a stable-channel release requested for testing with the existing Check for Update button. The new Durable Runtime itself remains EXPERIMENTAL and is OFF by default; publishing this release does not install or restart the user's running Qnector.

## Changes

- Protect MCP Streamable HTTP SSE responses with conditional 15-second keep-alive comments only between complete SSE frames, never in JSON/stdio. This does not extend ChatGPT Web model-response deadlines.
- Bound MCP JSON tool results to 256 KiB and base64 images to 2 MiB with explicit truncation metadata. No automatic replay of side-effecting commands.
- Add opt-in disk-backed daemon, Windows Job Host and task API: immediate durable task acknowledgment, idempotency keys, status, wait, result, paginated output and cancel. Adds a workspace-scoped Jobs preview panel; legacy synchronous tools remain unchanged.
- Redirect stdio console diagnostics to stderr to preserve JSON-RPC stdout; harden daemon ACL audit against a verified transient worker-file rename race.

## Validation

- Previous release candidate from the same functional changes: 291/291 tests across 61 files, typecheck, lint, Windows packaging and packaged daemon/recovery/stdio smoke passed. The v0.4.37 packaging gate and source provenance must pass again before assets are published.

## Important limitations / rollback

- Durable Preview is OFF by default (`QNECTOR_DURABLE_PREVIEW=1` opt-in). WorkflowManager has not fully migrated to the durable daemon; not all multi-step work survives a Desktop shutdown. Legacy MCP calls may still time out; this release does not guarantee ChatGPT Web network/model streaming uptime.
- Power-loss/reboot soak, full installed-app upgrade/drain/migration/rollback, cross-account ACL testing and 24-hour soak are not complete. Treat the Durable Preview as experimental despite the stable application update channel.
- Back up app configuration/workspace before enabling the preview, keep the v0.4.36 installer as a rollback option, and stop active jobs before manually switching versions. Releasing does not run the installer or restart the installed app.
