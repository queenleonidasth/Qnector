# Qnector v0.4.39 — explicit /long opt-in

- A user message starting `/long ` with a task description opts into long-task agent guidance; normal messages stay short by default. Explicit `long task` remains supported. `/long` alone does not submit a job.
- The agent prefers an available daemon-backed `tasks.start` with a stable idempotency key, returns the task ID as accepted rather than completed, and verifies final status using `tasks.get/result` later. If daemon tasks are unavailable, `process.start` is a non-durable fallback and must be described as such.
- Includes prior unreleased source changes from the durable runtime feature branch, including compact TypeScript symbol outlines and opt-in external Streamable HTTP MCP support. Khai-Hub remains disabled until separately authorized and validated.

Limitations: `/long` is an instruction in Qnector's MCP session bootstrap, not a native ChatGPT slash-menu entry or deterministic server-side chat-command parser. Durable daemon remains opt-in preview; this release does not establish that a disconnected browser will automatically resume AI reasoning. Do not replay uncertain side effects. No forced application restart is part of publishing.
