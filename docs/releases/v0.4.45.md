# Qnector v0.4.45 — Architecture and task visibility

This release integrates the previously isolated architecture refactor with the existing v0.4.44 English Memory Center and the preserved, opt-in Social Reader source. No existing user configuration, task journal or workspace is migrated automatically.

- Refactor the `system` MCP implementation into in-process Diagnostics, Skills, External MCP and Desktop UI adapters while retaining the same public tool, actions and Activity dispatcher. Some extended diagnostics remain in the central dispatcher; splitting source files is not a latency guarantee.
- Separate runtime service composition, the HTTP/SSE MCP host and the stdio MCP host. Preserve injectable services and stdio JSON-RPC-only stdout; SSE heartbeats are HTTP-specific and do not change ChatGPT client timeout budgets.
- Introduce the opt-in `tasks.overview` and `tasks.lookup` read-model facade, combining daemon-owned persistent jobs with session-scoped ProcessManager entries. The daemon remains the sole durable job owner; submission still requires a caller-stable idempotency key, cancellation remains explicit, and unknown outcomes are never replayed automatically. Session processes are not mislabeled as durable.
- Restore manual opt-in Agent Skills behavior (no mandatory routing or scanning on every MCP handshake); keep the English Memory Center introduced in v0.4.44.
- Include the Social Reader pilot's source and tests, but leave it disabled by default. YouTube support depends on optional local Agent Reach tools and available captions; Facebook authenticated reading remains unverified and is **not** advertised as enabled or production-ready. Do not start a browser session or change user authentication during an update.

**Validation:** Run merged-source TypeScript, ESLint, production build, complete regression, HTTP/stdio parity, native Windows Job Host and MCP smoke checks, followed by packaged executable/daemon recovery/update verification. Record evidence in the release log; only publish if those checks pass.

**Limitations:** Service and execution refactors are intentionally incremental: no silent migration of legacy `process` commands, no universal ChatGPT timeout fix, and no independently verified production Facebook connector. Keep previous `v0.4.44` as the rollback release if the new build fails validation.
