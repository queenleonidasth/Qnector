# Qnector v0.4.56 — Lean Context & Reliable Memory

## Improvements
- Compact `memory.working_set` by default, focused on the active task, high-value saved decisions and facts, the latest checkpoint, and recovery details. Use `details=true` for extended process/debug history and `sinceRevision` for low-cost unchanged/delta checks.
- Reduce repeated Superpowers instructions in Plan Mode: full local `using-superpowers`, `brainstorming`, and `writing-plans` are loaded at plan activation, while routine `mode.get` validates skills without repeating the full content.
- Improve ChatGPT Plan Mode action-schema versioning and MCP coverage for `mode.ask`, `mode.resolve` and `mode.finalize`. Continue enforcing discovery, explicit Q&A, plan finalization and revision approval before actions.
- Add opt-in `memory.record_turn` for explicitly authorized excerpts with task-scoped deduplication. Qnector cannot passively read every ChatGPT message, and local Qnector memory is separate from ChatGPT platform Memory.
- Add `memory.health` journal diagnostics and distinct timestamps for tool events, saved semantic facts, and explicitly recorded conversation excerpts in Memory Center.
- Improve host session-to-task correlation when supported session metadata is supplied.
- Reject malformed unified file patches instead of silently appearing successful.

## Compatibility and privacy
- Workspace Scope behavior is unchanged.
- No automatic capture of ChatGPT conversations. Recording a specific excerpt requires explicit opt-in; no browser cookie or token scraping is used.
- The ChatGPT MCP client may cache its old action schema. After updating Qnector, rescan/reconnect its custom ChatGPT app and verify that `mode` exposes `ask`, `resolve`, and `finalize`.
- Unsigned Windows Setup and Portable binaries may trigger a SmartScreen warning. Verify release SHA-256 before executing.
